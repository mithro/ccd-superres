How well each method did

Every score is measured against the true surface, which only the simulator knows. Lower error is better. The share of a bar group is 1.00 when the bars come out at their true strength and in the right place; below 0 means bright and dark are swapped, above 1 means the method has exaggerated them. A bar group counts as shown when its share is between 0.5 and 1.5, and the finest period shown is the smallest one reached, going from coarse to fine, before a group fails that test.

What these settings give

If the sensor passes over less than the whole surface, the rest cannot be recovered, the scores suffer and the position-solving methods can take many seconds.

True surface and reconstructions

Drag to move, scroll to zoom, double-click for the whole surface. Before it is drawn and scored, each reconstruction is slid sideways by up to three pixel spacings to where it best matches the true surface, because a scan cannot tell where the surface starts.

Raw readings

One row per frame, one column per pixel. Brighter is more light. This is all the reconstruction gets.

The path of the sensor

How far each frame was from where constant speed would put it. Solved paths are drawn with their overall offset removed, because the readings cannot fix it.

How much of each detail size survives the blur

1 means a pattern repeating at that distance reaches the readings at full strength, 0 means it is wiped out. Vertical marks are the bar groups of the test surface.

Keep these settings as an approach file

Save the text under approaches/ and name it in a comparison file to run it against the others with python -m ccdsr.compare.

Two dimensions

A small square sensor is scanned over a picture of line groups. The top row of groups varies along the scan, the bottom row across it. Without tilt every row of pixels retraces the same lines, and detail across the scan is lost. On this tab the reconstruction is told the exact position of every frame.
